## First BASS source-presence classifier: FROZEN

A source-neutral FullMix descriptor separates stable human Bass-present from stable Bass-absent at
**balanced accuracy 0.7908** against a **0.5000** majority baseline, using **one feature** and no PLP,
stems, quarter/measure or timing information.

- **Frozen feature:** `peak_prominence` (scipy find_peaks prominence, FullMix).
  Higher prominence is associated with BASS-ABSENT, point-biserial r = -0.5092.
- **Model:** L2 logistic regression, balanced class weights, C=1.0, threshold 0.50, seed 20260930.
- **Outputs:** BASS-present probability + binary class. **No uncertainty value** — with n=32 these
  are uncalibrated margins and must not be read as confidence.
- Frozen record: `docs/scientific/rfc/JGA-BASS-SOURCE-PRESENCE-CLASSIFIER-DEV-001-20260930/FROZEN_PIPELINE.json`.
- Label-blind predictor for the next task: `REPRODUCTION/predict_bass.py`. It reads the frozen record
  and the Phase A feature table and **never a label file**, so it cannot be used to open held-out
  answers. A named test asserts that by source inspection.

### The binding constraint is data, not features

The supervised-eligible development set is **32, not 40** (8 development landmarks are
human-unstable and excluded). At 2.0 observations per predictor:

- the 16-feature logistic scored 0.6883, **worse** than the single descriptor's 0.7908;
- adding FullMix low-band descriptors lowered balanced accuracy 0.7642 -> 0.7333;
- only 6 of 16 coefficients are sign-stable across folds;
- the RBF SVM fell to 0.5842-0.6242, at or below chance;
- the learning curve was still rising at the largest training size.

**More landmarks, not more features, is what this project needs.**

### Two errors I made and corrected before freezing

Both inflated my own numbers, and both are documented in the package.

1. I selected the decision threshold using the validation fold's own labels, which leaked each
   evaluation observation into its own prediction. It reported 0.8842 and 0.8625. **Both withdrawn.**
2. I fitted on raw features, so L2 shrinkage acted per-unit across features spanning 0.01 to 224549.
   In-fold `StandardScaler` was required by the PI and, once added, **changed the ranking**.

### The honest caveat on the frozen feature

`peak_prominence` topped a 16-descriptor sweep, so its cross-validated figure carries a selection
advantage. A nested estimate re-picking the best descriptor inside each fold gave 0.7558 — slightly
*below* the 16-feature model. On 32 rows the single descriptor and the multivariate model are not
cleanly separable, and that caveat cannot be removed.

### Threshold documentation correction (2026-09-30)

PI authorization `PI-BASS-FROZEN-THRESHOLD-DOC-CORRECTION-20260930`, task
`JGA-BASS-FROZEN-THRESHOLD-DOC-CORRECTION-001-20260930`, completed by opencode. **Documentation and
metadata only — no scientific change.**

A PI review audit confirmed the frozen `decision_threshold = 0.50` is correct, reproducible from
development data only, and was fixed before any held-out access. The audit did find a real
packaging hazard: the field named `threshold_mode` held `0.55` inside the
`development_cross_validation` block, where a reader would take it for the frozen threshold.

- `0.50` = preregistered inner-threshold procedure applied to all 32 eligible development rows.
  **Operative.** Unique optimum there (OOF balanced accuracy 0.825000 vs 0.808333 at 0.55), so the
  tie-break rule never fired.
- `0.55` = mode across the 50 outer-fold training fits. Distribution
  `{0.45: 1, 0.50: 18, 0.55: 20, 0.60: 11}`. **Non-operative; `predict_bass.py` must never use it.**

The field was renamed to `in_fold_threshold_mode_NOT_the_frozen_threshold` in `FROZEN_PIPELINE.json`
and `VALIDATION.json`, and a `threshold_documentation` block was added to both plus `REPORT.md`.
`REPRODUCTION/train_bass_classifier.py` was patched too, because it *emits* the field — leaving it
unpatched would have silently reverted the correction on any regeneration.

A flat 0.55 would have scored HIGHER development CV balanced accuracy (0.8200) than the frozen
0.7908. **This was deliberately not acted on** — substituting it would be tuning on development
cross-validation. The 0.45-0.60 spread shows the two values sit inside the noise of the
threshold-selection procedure at n=32 and corroborates the recorded HIGH overfitting risk.

Verified unchanged: frozen feature, coefficients, intercept, scaler mean/scale, hyperparameters,
`decision_threshold`, `frozen_at_utc`, and every CV metric. 28/28 named tests PASS. No retrain, no
