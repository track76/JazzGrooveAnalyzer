## Lifecycle and concurrency

Every writer: authority sync → Git/state → embargo → storage → backup preflight → authorized work → verification → artifact registration → relevant state updates → chat handoff → backup verification → optional PI-authorized Git operation → handoff → STOP PI.

One writer across agents/worktrees. All peers read-only and embargo-safe. Read-only modes cannot generate repository reports without a separately authorized writer block. Mode names do not confer permission. Before each write check current branch/HEAD, index, worktree, current registry/ledger, embargo, coordination and handoff; preserve unintegrated work. A changed baseline is STALE STATE / RESYNC REQUIRED. Unexpected changes require PI review, not automatic merge.

`python3 tools/jga_governance.py acquire --agent AGENT --task TASK --token UNIQUE_TOKEN` creates an exclusive lease in the common Git directory. Tokens identify a lease, are not credentials. Acquire requires a registry writer assignment and latest ledger event with exact write paths. `check-writer --token TOKEN` checks the saved baseline. `write --token TOKEN --target PATH --payload SMALL_PREPARED_FILE` checks scope/state, writes atomically and backs up through the existing helper, then checks for concurrent changes. `release --token TOKEN` only releases a current owner lease. A crashed/stale lease is not automatically stolen; PI resolves it after inspecting pending work. Do not refresh a stale baseline blindly.

The first installation is performed under one exclusive installation lease with equivalent per-write baseline checks; no other writer runs. This is not an ongoing exemption. File and Git guards are cooperative, not an OS sandbox: an ungoverned editor can bypass them. Do not claim prevention against malicious processes. Existing scientific tools are unchanged: any future writer must use a serialized authorized adapter and verify changes; no experiment is authorized now.

## Task admission

Before a regular agent can acquire a writer lease, PI (or a separately PI-authorized governance registrar) must record its task/mode/decision and exact write scope. This is a metadata-only admission block, serialized under an exclusive common-Git lease, with the same state/backup checks. It is not permission for an agent to assign itself its next scientific task. The regular acquire command fails closed for unregistered, read-only or revoked writers. If no authorized registrar is available, STOP PI; do not bypass the gate. Registry editing alone is not evidence of PI consent: the decision must cite the explicit PI instruction.

## Backup and verification classes

Existing `CONTINUOUS_EXTERNAL_BACKUP_AUTHORITY.md` remains unchanged. TEMPORARY_NO_BACKUP is allowed only for explicitly documented reproducible disposable scratch, never evidence needed to reproduce a result. The older external policy's automatic backup-debt wording does NOT override the newer PI-required stop/preflight gate.

Current mirror is `/Volumes/HD BackUp/JGA_BACKUP/JazzGrooveAnalyzer_CURRENT`; older INTERNAL_MAC and versioned copies are history, not current workspaces. Missing SSD mirror copies are reported as debt, not silently claimed in CURRENT. No orphan deletion. No full-terabyte hashes each task.

`external --mode metadata`: path existence and size; no integrity claim. `incremental`: hash records whose source metadata changed or lack previous verification, and required backup copies; unchanged ones rely on recorded verification. `full`: recompute hashes for every registered individual file and its backup; use on first registration, suspected corruption and milestone scope. Directory sets require a separate member manifest/full traversal before certification. FULL means FULL REGISTERED SCOPE, not every SSD file. Every command reports scope and missing/mismatch findings; never repairs.

`check` validates registered ledger/decision/path/embargo references, handoff Git identity, bootstrap parity and document links. Missing historical references are reported, not repaired without PI approval. New task external IDs must exist in the external manifest. A complete free-text historical reference census is not guaranteed; add required manifests at task admission. Backup PASS must name scope/date; BACKUP_FAIL prevents safe completion. Backup exclusions are exactly those of the existing helper, not broad new scientific ignore rules.
